# 4. 第一次对话

先进入你要处理的项目目录。ap 以启动目录作为项目根，会话也按这个目录归档。

```sh
AP_BIN=/path/to/ap/build/ap
cd ~/projects/ap
"$AP_BIN" --print "找出读取配置的代码，给出文件和行号。只读，不要修改文件。"
```

把 `~/projects/ap` 换成你的项目目录，把 `AP_BIN` 换成你的构建产物路径。`AP_BIN` 只是 shell 变量，不是 ap 的配置项。Windows 写对应的 `.exe` 路径。提示词用双引号包住时，里面的单引号、括号和中文都可以正常使用。

## 你会看到什么

ap 把输出分成两路：

- **stdout** 放最终答案。
- **stderr** 放执行过程：工具开始、工具输出、重试、取消、续聊提示。

终端里两路通常交织显示。第一次运行时，重点看三样东西：

1. 它调用了哪些工具。工具开始是一行 `◆ <工具名> (<参数摘要>)`。
2. 工具是否成功。结束行是 `✓ <耗时>ms exit <code>` 或 `✗ <耗时>ms <错误>`。
3. 最后有没有答案。答案只在 turn 结束后写到 stdout。

## 拿到 session id

正常结束后，stderr 会打印：

```text
---

continue with -s ses_20261022_120000_abcdef123456
```

`ses_...` 就是这次会话的 id。保存它，下一轮可以接着聊。

## 继续上一次对话

```sh
"$AP_BIN" -s ses_20261022_120000_abcdef123456 --print "继续，把刚才的文件完整解释一遍"
```

如果这是当前项目最近的一次根会话，也可以直接：

```sh
"$AP_BIN" -c --print "继续"
```

`-c` 只在当前项目内查找最近的根会话。子代理会话不参与。从子目录启动会落到不同的项目，找不到父目录的会话。

## 第一次使用的检查清单

- [ ] `"$AP_BIN" --version` 能打印版本。
- [ ] 配置文件能被读取，模型能返回一句话。
- [ ] 一次只读任务能给出文件和行号。
- [ ] 记下 session id，能用 `-s` 恢复。
- [ ] 看懂 `◆`、`✓`、`✗` 三种标记。
- [ ] 知道最终答案在 stdout，过程在 stderr。

## 如果第一次就失败

先看退出码和 stderr 的最后几行：

| 现象 | 先检查 |
| --- | --- |
| 提示模型未配置 | 配置文件里有没有 `model` |
| 提示找不到 session | 是否在创建会话的同一目录运行 |
| 提示找不到 bash | 是否安装了 Git for Windows，或 `AP_BASH` 是否正确 |
| 401 或 403 | API key 是否有效 |
| 一直没有输出 | 网络是否能到达 `base_url` |

完整的排查路径见 [第 17 章](17-troubleshooting.md)。下一章讲怎么把任务写清楚，减少来回。
