# 12. 让 ap 记住项目规矩

ap 在新建会话时把两层记忆注入 system prompt：

- 全局记忆：`~/.agents/AGENTS.md`
- 项目记忆：从启动目录向上查找的 `AGENTS.md`

它们只影响新会话。恢复旧会话时使用冻结的 system prompt，不会重新读取。

## 全局记忆

位置固定：

```text
~/.agents/AGENTS.md
```

适合放跨项目通用的偏好，例如：

- 回答默认用中文。
- 修改前先读相关测试。
- 不要自动提交 git。
- 命令输出太长时先过滤。

## 项目记忆

ap 从启动目录开始向上找 `AGENTS.md`：

1. 包含启动目录本身。
2. 当前目录或祖先有 `.git` 时，查到该目录为止。
3. 没有 `.git` 时，一直查到文件系统根。
4. 目录名以 `.` 开头的层级不读取。
5. 只读名为 `AGENTS.md` 的普通文件，不读子目录。

收集顺序是从近到远，注入时反转为远到近。多个文件冲突时，更近的文件排在后面，按提示词层约定以它为准。ap 不会强制合并规则。

## 该写什么

项目记忆是给模型的指令，不是权限系统。写得越具体，越容易被遵守。

适合写：

- 构建、测试、格式化的准确命令。
- 代码风格和命名约定。
- 目录职责和不能跨的边界。
- 已知的坑和禁止改动的文件。
- 提交信息和 PR 的约定。
- 验收标准。

不要写：

- “写得优雅一点”这类无法验证的要求。
- 大段架构文档。需要时给路径，让模型自己读。
- 密钥、令牌、客户数据。
- 你并不希望模型执行的命令。

例子：

```markdown
# 项目约定

- 构建：./build.sh
- 测试：./test.sh，提交前必须通过。
- Go/Odin 文件用 tab 缩进，注释用中文。
- 不要改 ap-web/dist/，它由 npm --prefix ap-web run build 生成。
- 修改 arguments 或输出格式时，同步 docs/ 和测试。
```

## 替换基础提示词

`$AP_CONFIG/SYSTEM.md` 存在时，会替换 ap 内置的基础提示词段。工具说明、环境信息、记忆和技能清单仍然照常拼接。

只在新会话生效。恢复和 fork 使用冻结值。

不要用 `SYSTEM.md` 清空安全提示或工具说明。ap 没有“清空全部提示词”的模式，环境、工具说明等小节始终保留。

## 关闭记忆注入

```sh
./build/ap --no-agents-md --print "..."
```

`--no-agents-md` 同时关闭全局和项目记忆的读取与注入。它不改变磁盘上的文件，也不是沙箱。

`--no-skills` 关闭技能扫描，见 [第 13 章](13-skills.md)。

两个开关都只影响新会话。恢复会话时既不改变冻结的 prompt，也不产生 warning。

## 检查实际注入的内容

```sh
./build/ap --print-system-prompt --no-skills
```

它会打印完整 system prompt 后退出，不创建会话，不调用模型。确认记忆段落是否出现、顺序是否对。

加 `-s` 或 `-c` 时，打印该会话冻结的 prompt，而不是重新组装的结果。

## 记住一条边界

记忆是提示词，不是审批或权限。模型可能忽略它，也可能被其他文本覆盖。真正不能碰的东西，应该放在版本控制、备份和最小权限账户里，而不是只写在 `AGENTS.md`。
