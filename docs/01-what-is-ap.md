# 1. ap 是什么

ap 是一个命令行 coding agent。你给它一条任务，它请求模型、执行工具、把结果送回模型，重复这个过程，直到任务完成或命中终止条件。一次运行处理一条提示词，然后退出。

它不是一个聊天窗口，也不是 IDE 插件。`ap-tui` 和 `ap-web` 是另外两个前端，它们每轮启动一个 `ap` 子进程，把事件渲染成终端界面或网页。

## 一次运行会发生什么

1. 你给 ap 一条提示词。
2. ap 把提示词、项目规则和可用工具一起发给模型。
3. 模型要求读取文件、修改文件或运行命令。
4. ap 执行这些工具，把结果交回模型。
5. 模型继续判断，直到给出最终回答或停下来。

这个循环叫 ReAct。你不需要手动安排每一步，但需要知道它可能连续执行很多步。默认单个 turn 最多 100 步。

## 它能做什么

ap 只有五个工具：

- 读取文件。
- 写入文件。
- 按原文替换文件片段。
- 运行 Bash 命令。
- 启动一个子代理处理独立任务。

依靠这些工具，它可以定位代码、解释实现、修改文件、跑测试、批量重命名、整理文档、检查配置。它也能读取图片，但需要先在配置里打开 `image_input`，并使用支持视觉的模型。

## 它不做什么

- 没有审批弹窗、权限规则和沙箱。工具调用直接执行。
- 不自动提交 git，也不自动回滚修改。
- 不接管编辑器，没有补全、悬浮提示或内联 diff。
- 不做对话压缩。上下文快满时只省略较早的工具输出，仍不够就交接给新会话。
- 不支持 hooks、plan mode、MCP、插件系统、向量记忆和联网搜索工具。
- 不提供内置的远程服务。`ap-web` 默认只监听本机。

完整的不支持清单见 [第 20 章](20-files-and-terms.md#当前不支持的功能)。

## 三种用法

| 用法 | 入口 | 适合 |
| --- | --- | --- |
| 一次性命令行 | `ap` | 问一句就走、脚本、批处理、子代理 |
| 终端界面 | `ap-tui` | 在一个窗口里连续对话，保留滚动历史 |
| 浏览器界面 | `ap-web` | 多标签页、多工作空间、鼠标操作 |

三者调用同一个 agent 内核。命令行参数、输出格式和事件协议保持一致。你可以先用命令行跑通，再换界面。

## 适合交给它的任务

- 在一个仓库里找实现，要求给出文件和行号。
- 解释一段代码或一次报错。
- 做范围明确的小改动，并运行测试。
- 批量修改同类文件。
- 把一个独立的小调查交给子代理。

## 不适合交给它的任务

- 无人看管地修改生产环境。
- 处理你不允许模型看到的密钥、客户数据或隐私文件。
- 需要精确审批链和权限隔离的合规场景。
- 需要长时间驻留的后台服务。每次 `bash` 都是独立进程，`cd` 不会跨调用保留。
