# 14. 定义专用代理

代理是一套预设：提示词正文、工具白名单、可选的模型和步数上限。它适合把“总是用同一种方式做某类任务”固化下来。

ap 内置一个代理 `general`，使用全部五个工具。

## 定义文件

位置是：

```text
$AP_CONFIG/agents/<name>.md
```

文件名就是代理名。格式是简化的 frontmatter 加正文：

```markdown
---
name: scout
description: 搜索代码库，回答“这个功能实现在哪”这类问题
tools: read_file, bash
max_steps: 30
---

你是一个搜索代理。用 bash 里的 grep 和 find 定位，用 read_file 确认。
最终回答必须给出具体的文件路径与行号。
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `name` | 是 | 必须与文件名一致 |
| `description` | 是 | 一句话说明什么时候该用 |
| `tools` | 否 | 逗号分隔的工具白名单。不写时使用全部已注册工具 |
| `model` | 否 | 直接运行时覆盖模型 |
| `max_steps` | 否 | 直接运行时覆盖步数上限 |

正文会作为 `## Agent 定义 (<name>)` 追加到 system prompt。它只补充指令，不替换基础提示词、工具说明、环境或记忆。

`tools:` 一旦出现就是显式白名单，即使值为空也不会回退到全部工具。列表里有未知工具名时，新会话启动失败并退出 2。

## 直接运行

```sh
./build/ap --agent scout --print "找出读取配置的代码"
```

命令行优先级最高：

```text
命令行 > 代理定义 > settings.json
```

`max_tokens` 没有代理定义这一级，只取命令行或 `settings.json`。

## 子代理

模型可以在一个 turn 里调用 `task` 工具，启动一个独立 ap 进程完成自包含任务。

- 子代理有独立上下文、独立 transcript 和独立工具集。
- 完成后只把最后一条含文本的回答交回父进程。
- 父进程的工具串行执行，同一时刻只有一个子代理。
- 默认最大嵌套深度是 `1`。达到上限时，`task` 从工具集移除。
- 子代理写文件不隔离，和父进程操作同一工作目录。
- 子进程的完整过程可以用 `ap -s <child_session_id>` 在同一项目内查看。

调用示例：

```text
用 scout 代理调查“配置解析在哪里实现”，只返回文件路径和行号。
```

父进程会启动 `--agent scout` 的子进程，把子代理的最终回答放进工具结果。

## 通过 task 运行时的参数

由 `task` 拉起的子代理，`model` 和 `max_steps` 来自父会话的生效值。子进程的命令行参数优先级高于代理定义，所以子代理不会使用自己定义文件里的 `model` 和 `max_steps`。

这两个字段只在通过 `ap --agent <name>` 直接运行、且命令行没有覆盖时生效。

## 工具白名单不是权限

`tools:` 只决定模型能看到哪些工具。它不是权限系统，也不是沙箱。

只要 `bash` 还在白名单里，代理就拥有完整的进程权限，可以读写工作目录之外的文件，也可以运行任意命令。需要更窄的能力时，去掉 `bash` 和 `write_file`，只留 `read_file`。

## 什么时候值得定义代理

- 你反复用同一段提示词做同类调查。
- 你希望某类任务只能用只读工具。
- 你想给某类任务固定的步数上限或模型。
- 你想让子代理有明确的分工和输出格式。

如果只是一次性任务，直接写提示词更简单。代理定义适合长期复用。
