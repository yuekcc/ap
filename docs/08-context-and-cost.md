# 8. 控制时间与花费

一次运行处理一条提示词，这叫一个 turn。一个 turn 里可能有一次或多次模型调用，每次逻辑调用叫一个 step。网络重试不算新的 step。

三个参数最常用：

| 参数 | 管什么 | 默认 |
| --- | --- | --- |
| `--max-steps` | 单个 turn 最多几次模型调用 | 100 |
| `--max-tokens` | 单次响应最多多少 token | 65536 |
| `--context-window` | 模型上下文窗口多大 | 1048576 |

```sh
./build/ap --max-steps 30 --print "只调查，不修改，给出结论"
./build/ap --max-tokens 8192 --print "用不超过一屏的文字解释这个模块"
./build/ap --context-window 32768 --print "..."
```

`--max-steps` 和 `--max-tokens` 必须是正整数。`--context-window` 必须是非负整数。`0` 表示关闭预算，和不传不等价。

## 上下文快满时发生什么

ap 按模型窗口做预算。接近上限时，它按顺序做两件事：

1. 省略较早的大工具输出。把旧结果替换成固定桩文本，对话文本不动。
2. 省略后仍然不够，就生成交接文档，创建新会话承载它。

ap 不做对话压缩。assistant 文本和用户提示词永远不会被改写。只有工具结果会被省略，而且失败的工具结果和最近的几条结果不会被省略。

省略是投影层的行为，不改 transcript。你仍然可以在原始记录里找到完整内容。

## 两个开关的差别

| 设置 | 预算 | 自动交接 | 超限时 |
| --- | --- | --- | --- |
| 默认 | 开 | 开 | 自动交接，正常结束 |
| `--no-handoff` | 开 | 关 | 退出 3，`context_too_long` |
| `--context-window 0` | 关 | 关 | 退出 3，`context_too_long`，手动 `--handoff` 仍可用 |

`--no-handoff` 只关自动交接，预算仍然工作。`--context-window 0` 把整套上下文管理关掉。

## 什么时候该开新会话

- 换了一个不相关的任务。
- 之前贴了很长的日志或文件，已经不再需要。
- 连续多次失败，旧的错误信息一直在干扰模型。
- 上下文快满，自动交接已经发生。
- 你想保留当前会话作为记录，同时在干净上下文里尝试新方案。

开新会话比继续硬撑便宜，也更稳定。需要保留结论时，先让它写一份简短总结，再开新会话把总结带过去。

## 花费从哪里看

ap 不计算金额，只报告 token。用 `--output-format json` 能看到本次的 `usage`：

```json
{
  "session_id": "ses_...",
  "result": "...",
  "stop_reason": "stop",
  "num_steps": 3,
  "usage": {
    "input_tokens": 12345,
    "output_tokens": 678,
    "cached_tokens": 0,
    "reasoning_tokens": 0,
    "total_tokens": 13023
  }
}
```

`max_tokens` 是单次响应的天花板，不是整个 turn 的总量。`num_steps` 是实际调用次数。真正的账单由模型服务商计算。

## 省钱的几个做法

- 把范围写小，指定要看的文件。
- 不要一次贴几万行日志，先让它用 `bash` 过滤。
- 调查阶段用 `--max-steps` 限制，确认方案后再放开。
- 任务结束时让它给三点总结，下一轮只带总结。
- 不需要自动交接时用 `--no-handoff`，失败得更早，避免额外调用。
