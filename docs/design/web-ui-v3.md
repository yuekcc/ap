# ap-web 界面 v3：三栏工作台

> 设计稿：[v3.png](v3.png)（Excalidraw 场景，标注为红色）
> 状态：已实现（v3）。定稿行为已同步到 [../internal/web.md](../internal/web.md) 与 [../11-web.md](../11-web.md)。
> 影响范围：只改 `ap-web` 前端。HTTP API、SSE 帧格式、transcript 和 `ap` 本体不动。
> 实现补充：三栏布局不变，视图层已从 Alpine.js 迁移到 alien-signals + 原生 DOM，见 [../internal/proposals/web-alien-signals.md](../internal/proposals/web-alien-signals.md)。

## 问题陈述

现在的 `ap-web` 是一条顶栏加左右两栏：顶栏放 logo、横向工作空间分段控件、「+」、打开目录/终端的两个按钮；左栏是「开启新对话」加当前工作空间的对话记录（按今天/昨天/前天/更早分组）；右栏是标题、消息区和录入框。

用久了会撞上四个问题。

1. **工作空间是横向标签，数量一多就被挤成一行滚动**，当前在哪、有哪些项目不直观，也没有位置放「排序」「折叠」这类工作空间级操作。
2. **对话记录和「当前这一轮」抢同一块横向空间**。对话记录只有一栏宽，切换工作空间和切换对话这两个不同粒度的操作挤在同一个视觉层里。
3. **状态信息藏在文字里**。哪个对话在跑、哪个工具失败了，现在靠「运行中」这种文字和 `data-status` 换了颜色的边框，扫一眼看不出来。
4. **模型名、agent 名、token 用量、外部程序入口全堆在顶栏**，主区的标题行反而只有标题和刷新按钮，信息层级是反的。

## 方案

把界面从「顶栏 + 两栏」改成**三栏工作台**：左边是工作空间栏，中间是当前工作空间的对话栏，右边是对话正文。顶栏消失，原本挂在顶栏上的操作下沉到各栏自己的标题行。三个区域的职责一次说清：左栏回答「我在哪个项目」，中栏回答「这个项目里有哪几次对话」，右栏回答「这次对话进行到哪了」。

```text
┌───────────────────┬───────────────────┬────────────────────────────────────────┐
│ ap  [+] [⇅] [⇤]   │ 对话   [🗁] [⌘]   │ 修改 XXX 文件  [↻]        26.4M tokens │
├───────────────────┼───────────────────┼────────────────────────────────────────┤
│ ▸ project_current │ ＋ 新对话          │                    [当前修改的文件]    │
│   project_a       │ ┌───────────────┐ │ ● Bash  ls && mkdir -p xxx             │
│   project_b       │ │ 修改 XXX 文件  │ │ ● Bash  ls && mkdir -p xxx             │
│   project_c       │ │ 10-16 12:22 ● │ │                                        │
│                   │ └───────────────┘ │ 已提交 cfae130 feat(web)：渲染 Markdown │
│                   │                   │ 中的 mermaid 图表。                    │
│                   │                   │                                        │
│                   │                   │ ┌────────────────────────────────────┐ │
│                   │                   │ │ 给 ap 一个提示词…                  │ │
│                   │                   │ │ z:/xxx/project_current [交接] [↑]  │ │
│                   │                   │ └────────────────────────────────────┘ │
└───────────────────┴───────────────────┴────────────────────────────────────────┘
   工作空间栏           对话栏                     对话正文
```

设计稿里每个元素和实现的对应关系见文末「附录：设计稿元素映射」。三栏分界：

| 区域 | 宽度 | 底色 | 职责 |
| --- | --- | --- | --- |
| 工作空间栏 | 默认 260px，可拖动 176–420px，可折叠 | `--bg-grouped` | logo、工作空间列表、工作空间级操作 |
| 对话栏 | 默认 260px，可拖动 176–420px，窄屏自动折叠 | `--bg` | 当前工作空间的对话列表、对话级操作 |
| 对话正文 | `minmax(0, 1fr)` | `--bg` | 标题行、消息流、录入框 |

## 用户故事

1. 作为 ap-web 用户，我想让工作空间以竖列表格呈现，这样项目多的时候不用横向滚动。
2. 作为同时处理多个仓库的用户，我想一眼看出哪个工作空间是当前项目，这样我知道新对话会落在哪个目录。
3. 作为用户，我想用「+」打开系统目录选择框并把它加成新的工作空间，这样我可以直接切到另一个仓库。
4. 作为用户，我想让工作空间列表记住上次的顺序偏好，这样我刷新页面后不必重新调整。
5. 作为用户，我想用「排序」在「最近活动」和「名称」之间切换，这样我能控制列表按什么维度排序。
6. 作为用户，我想折叠工作空间栏腾出横向空间，这样我在小屏或分屏下能看更多正文。
7. 作为用户，我想在折叠工作空间栏后仍有一个明显的入口重新展开它，这样我不会把自己关在单栏里。
8. 作为用户，我想让对话栏单独成栏，这样切换工作空间和切换对话是两个互不干扰的操作。
9. 作为用户，我想在对话栏标题行直接打开当前工作目录的文件管理器和终端，这样不用先回到主区。
10. 作为用户，我想用「新对话」按钮在当前工作空间里开一轮空对话，这样我开始新任务时不会先撞进旧会话。
11. 作为用户，我想在对话列表里看到每条对话的标题，这样我能认出想回到的那次对话。
12. 作为用户，我想在对话列表里看到每条对话的本地时间，这样我知道它是什么时候跑的。
13. 作为用户，我想在对话列表里看到每条对话的工作状态点，这样我能看出哪次对话还在跑。
14. 作为用户，我想让正在跑的那条对话有持续但不刺眼的动效，这样我知道点击别处不会打断它。
15. 作为在另一个标签页里跑着任务的用户，我想在当前标签页看到那条对话仍在运行，这样我不会重复发提示词。
16. 作为用户，我想让对话列表按今天、昨天、7天内、更早分组，这样长历史里我能快速跳到想回的那一次，短历史又不会出现空组标题。
17. 作为用户，我想在主区标题行看到会话标题，这样我知道当前这一轮在干什么。
18. 作为用户，我想用标题旁的刷新按钮重新生成标题，这样跑偏的标题可以重来一次。
19. 作为用户，我想在主区标题行看到本次会话的累计 token 用量，这样我能判断这一轮值不值得继续。
20. 作为用户，我想在鼠标悬停 token 用量时看到模型、agent 和输入/输出/缓存分项，这样我不必为了看一眼模型名去找别的入口。
21. 作为用户，我想在主区看到一个「当前修改的文件」指示，这样长会话里我能知道 agent 刚动过哪个文件。
22. 作为用户，我想点击那个指示复制完整路径，这样我可以把它粘到编辑器里。
23. 作为用户，我想让工具卡片左侧有状态点（运行中、成功、失败），这样我扫一眼就知道哪一步出了问题。
24. 作为用户，我想让工具卡片默认折叠只留名称、参数摘要和耗时，这样长命令输出不会把消息流冲散。
25. 作为用户，我想让助手文本按 Markdown 渲染（含 mermaid 图表），这样回答里的表格、代码块和流程图能直接读。
26. 作为用户，我想让用户输入和工具输出保持纯文本，这样任何内容都不会被当作 HTML 执行。
27. 作为用户，我想在录入框里用 Enter 发送、Shift+Enter 换行，这样我不必离开键盘。
28. 作为用户，我想让录入框底部左侧回显当前工作空间路径，这样发送前我能确认落在哪个目录。
29. 作为用户，我想让「交接」和「发送」排在录入框右下角同一组，这样主操作只有一处。
30. 作为用户，我想在运行中把「发送」换成「停止」，这样我不会误发第二条提示词。
31. 作为用户，我想让三个区域各自滚动、消息区翻上去时露出「回到底部」，这样我不必被迫跟随流式输出。
32. 作为把浏览器窗口缩窄的用户，我想让工作空间栏先折叠、对话栏再折叠，这样 13 寸屏上正文仍然可读。
33. 作为键盘和读屏用户，我想让当前工作空间、当前对话带 `aria-current`，折叠按钮带 `aria-expanded`，这样我能知道自己在哪。
34. 作为用户，我想在切到一个还没有落盘对话的工作空间时看到一条「新会话」占位，这样空目录不会看起来像坏了。
35. 作为维护者，我想让这次改版只动前端，这样 HTTP API、SSE 帧格式和 transcript 契约都不用重新验证。
36. 作为维护者，我想让新布局的结构断言留在前端测试里，这样下次改版不会又把入口挪回顶栏。

## 实现决策

### 骨架

- 页面骨架从「标题栏 + 左栏 + 右栏」改成**单行三栏 flex**：左栏 `var(--rail-w)`、中栏 `var(--sessions-w)`、右栏 `flex: 1 1 auto`。用 flex 而不是 grid，是因为折叠一栏只需要 `display: none`，不必重算 grid 轨道；窄屏把侧栏改成 `position: fixed` 浮层时也不牵扯轨道。
- 删除顶栏这个 DOM 层，不再保留 `titlebar` 折叠状态。原顶栏的 workspace 分段控件改写成工作空间栏的竖列表；原顶栏右侧的「打开文件管理器 / 打开终端」移到对话栏标题行；model / agent chip 从主区标题行移除（信息并入 token 用量提示）。
- 主区保留现有三段式 `grid-template-rows: auto minmax(0, 1fr) auto`：标题行、消息区、录入框。消息区仍是唯一的滚动容器，宽度上限继续用 `--maxw`，在变窄的主区里水平居中；设计稿里正文列比栏窄只是画布缩放，不据此改排版宽度。
- 三栏之间用 1px `--separator-soft` 分隔，不再用卡片投影或圆角外框，延续现有 iOS 18 扁平分组语言。只保留浅色主题。

### 工作空间栏

- 结构：标题行（logo + 三个图标按钮）、工作空间列表。标题行图标依次是「打开新工作空间」「排序」「折叠工作空间栏」。
- logo 现在是 `ap` 字标，保持不变，只是从顶栏移到本栏标题行左侧。
- 工作空间项：整块可点，当前项用 `--accent-tint` 浅底 + 常规文字色，其余透明底 + 次级文字色；悬停给 `--fill-2`。`aria-current="true"` 标当前项，`title` 放完整路径。
- 切换工作空间沿用现有语义：打开该目录最近一条已落盘对话，没有就开新 slot（不新增接口）。
- 宽度：本栏和对话栏的右边界各有一个分隔条（`role="separator"`，`tabindex="0"`）。指针拖动调宽，方向键 ±16px（Shift ±64px），`Home`/`End` 到两端，双击回默认 260px。宽度写进 `.app` 的行内 `--rail-w` / `--sessions-w`，偏好存 `localStorage`，非法值或越界都收在 176–420px，且不超过视口宽度的 35%。窄屏两栏是浮层，分隔条一并收起。
- 折叠：本栏宽度归零后，「展开工作空间栏」按钮**移到对话栏标题行最左**，保证任何时刻都有展开入口。折叠状态存 `localStorage`，键沿用现在的 sidebar 折叠键。
- 排序：标题行「排序」是一个小菜单，选项为「最近活动」「名称」，默认「最近活动」。偏好存 `localStorage`，同时作用于工作空间列表和对话列表。排序在浏览器本地完成，请求 `/api/projects` 后重排，不改服务端返回顺序。

### 对话栏

- 标题行：「对话」标签 + 右侧两个图标按钮（打开文件管理器、打开终端）。两个按钮作用于**当前工作空间目录**，复用现有 `POST /api/cwd/reveal`、`POST /api/cwd/terminal`，不按对话区分。
- 「新对话」按钮独占一行，放在列表上方，替代现在左栏的「开启新对话」。外观是 outline（1px `--accent-line` 描边、透明底、systemBlue 文字），图标与文字作为一组居中，悬停才铺 `--accent-tint` 浅底。
- 对话项：两行布局，第一行标题，第二行左侧本地时间、右侧状态点。当前对话 `aria-current="true"` 并用 `--accent-tint` 整块高亮。
- **按时间分组**：会话按浏览器本地自然日分成「今天 / 昨天 / 7天内（2–7 天前）/ 更早」，空组不渲染，取不到时间戳的落进「更早」。分组是纯派生：组内顺序跟随排序偏好，组本身的先后固定，服务端返回顺序不动。时间戳同时留在每条的第二行，分组标题只做弱提示。
- 状态点：`session.running` 为真时是脉冲实心点（`--accent`），否则是 `--fg-3` 的静态点（只在当前对话上显示静态点，其余不画，减少噪声）。脉冲动效在 `prefers-reduced-motion: reduce` 下停用。
- 运行态来源保持事件驱动：本标签页的 turn 起止、切换对话、开新 slot 后刷新 `/api/projects`；不新增轮询，其他标签页的状态可能与实际有延迟（与现状一致，写进已知限制）。
- 新 slot 尚未落盘时保留「新会话」占位项（沿用现在的 draft 对话语义）。

### 对话正文

- 标题行：左侧会话标题 + 刷新按钮，右侧 token 用量。刷新按钮沿用现有 `POST /api/session/title`，运行中和未落盘时不可点。
- token 用量沿用 `usageLabel`（本会话累计，来自 `session_end` / `turn_end`），`title` 由 `usageTitle` 扩展，把 `model · agent` 一起带进悬停提示，替代被移除的两个 chip。
- 「当前修改的文件」：消息流上方的右对齐小指示，显示本会话最近一次 `write_file` / `edit_file` 的 `file_path`，只显示文件名，`title` 给完整路径；没有改动时整块不显示。点击把完整路径写入剪贴板，失败时落一条 notice。路径从工具事件的 `args.file_path` 取（live 事件和 `/api/history` 回放事件都保留了 `args`），因此在 `render.js` 里给工具条目补一个 `path` 字段即可，不需要服务端配合。
- 工具卡片：头部左侧状态点（运行中 `--accent` 脉冲、成功 `--ok`、失败 `--bad`），后面依次是工具名、单行参数摘要、耗时、退出码；整行圆角，默认折叠，展开看完整输出，沿用现有 `details` 结构与截断提示。
- 助手文本继续走 `markdown-exit`，`html: false`、`linkify: true`、`breaks: true`；mermaid 围栏占位在消息结束后替换成 SVG，`securityLevel` 仍是 `strict`。用户输入和工具输出继续用 `textContent`。
- 空状态：「今天要做什么？」和提示文案保留，只是宽度上限跟着主区内容列走。

### 录入框

- 结构不变：圆角输入区里上面是 textarea，下面是操作行。
- 操作行右侧一组：运行中显示「停止」，否则显示「发送」；左侧「交接」移到右侧操作组，与发送相邻。左侧只留当前工作空间路径回显。
- 「交接」语义不变：把当前会话交接给新会话，输入框里的文字作为交接后的首个提示词，复用现有 `/api/turn` 的 `handoff` 分支。
- Enter 发送 / Shift+Enter 换行 / 输入法合成期间不发送，保持现状。

### 响应式

- `≤ 1100px`：工作空间栏变成左侧浮层（`position: fixed`，宽度 `min(16rem, 80vw)`），默认收起，展开入口落在对话栏标题行；浮层下面的遮罩点一下收起。折叠偏好与手动折叠分开记录，窗口变宽后回到用户自己的选择。
- `≤ 820px`：对话栏也折叠，主区全宽；对话栏以标题行左侧一个「对话记录」按钮打开的浮层呈现，点遮罩或选中一项后关闭。浮层里的对话项仍是竖排两行，不改成胶囊——两行结构放不下胶囊。
- 窄屏录入框字号不低于 16px，避免 iOS 聚焦时自动放大。

### 接口与契约

- **不新增、不修改任何 HTTP 端点，不改 SSE 帧格式**。三栏所需数据全部来自现有 `/api/projects`（含 `running`、`ts`、`title`）、`/api/sessions`、`/api/history`、`/api/session/title`、`/api/cwd/reveal`、`/api/cwd/terminal`。
- 排序、折叠、当前修改文件、状态点展示都是纯前端派生，服务端返回顺序和字段保持原样。
- transcript 只追加、`context_build` 纯函数、stdout 机器通道、取消及时性等契约不受影响：本轮没有触碰 `ap-core`、`ap-cli` 或 `ap` 的任何代码路径。

## 测试决策

好测试的标准：断言用户能观察到的行为和文档里写死的信息架构，不断言实现细节（不查 class 名数量、不查具体像素值、不依赖 Alpine 内部状态）。本项目没有 DOM 测试依赖，所以继续用「读源码做结构断言 + 纯函数单测」两层，不引入 jsdom。

1. **主 seam：`ap-web/frontend/markup.test.mjs`**（读 `index.html` 与 `styles.css` 做结构断言）。这是本次改版唯一必须改的测试文件。现有用例里有 5 条直接描述旧布局，需要**改写成新布局的断言，而不是删掉**：
   - 「顶部是工作空间标签，侧栏承载新对话与当前空间的对话记录」→ 拆成「三栏 grid：工作空间栏 / 对话栏 / 正文」「工作空间是竖列表而不是顶部标签」。
   - 「侧栏折叠入口在标题行左侧」「对话标题行居中，两侧分别是折叠入口与环境状态」→ 改写为「折叠入口在工作空间栏标题行，折叠后可展开入口出现在对话栏标题行」。
   - 「顶栏右侧是在工作目录打开文件管理器与终端的两个按钮」→ 改写为「两个按钮在对话栏标题行」。
   - 「工作区顶栏展示 token 用量」→ 改写为「主区标题行展示会话累计 token，模型与 agent 在悬停提示里」。
   - 「输入区只回显工作空间路径」「交接入口在输入框下方」→ 改为「交接与发送在同一操作组」。
   另新增：对话项含时间与状态点；工具卡片头部含状态点；当前修改文件指示存在且默认隐藏；`aria-current` / `aria-expanded` 保留；只提供浅色主题、无模糊无渐变仍然成立。

## 不在范围

- 深色主题、主题切换。设计稿是线稿，没有深色版本。
- diff 渲染、改动文件列表、代码高亮。设计稿只画了「当前修改的文件」这一个指示，不做改动汇总面板。
- 对话的重命名、删除、归档、fork、拖拽排序，以及工作空间的移除。
- 多标签页之间的实时状态同步（不引入轮询、WebSocket 或服务端广播运行态）。
- 文件附件上传、图片粘贴、语音输入。
- `Last-Event-ID` 断点续传。
- 鉴权、HTTPS、远程访问模式。
- 任何 `ap`、`ap-core`、`ap-cli`、`ap-tui` 的改动；`ap-tui` 不跟着改版。

## 待定问题

这三处设计稿有标注、没有细节，需要在评审时定下来，目前的默认取舍写在后面：

1. **「修改当前文件」的语义**。默认按「最近一次被 agent 改写的文件指示 + 点击复制路径」实现。若本意是「列出本会话所有改动文件」或「打开文件预览」，就要新增接口与面板，属于独立提案。
2. **「排序」作用对象**。默认是工作空间列表与对话列表共用一个偏好。若只想排工作空间，对话列表就固定按最近活动。
3. **「26.4M Tokens」的口径**。默认是本会话累计（现有 `usageTotal`）。若要显示当前工作空间或全部历史的累计，就需要服务端在 session 摘要里补 usage 汇总，属于服务端改动。
