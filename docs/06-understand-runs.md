# 6. 看懂执行过程

ap 的输出分两路。看懂这两路，比记住每个参数更重要。

| 通道 | 内容 | 用途 |
| --- | --- | --- |
| stdout | 最终答案，或 `json`、`stream-json` 的结果与事件 | 机器读取，脚本解析 |
| stderr | 工具调用、工具输出、重试、取消、续聊提示 | 人看过程，排查问题 |

三种输出格式都遵守这一条。日志和进度不会混进 stdout。

## text 模式的标记

```text
◆ read_file (ap-cli/options.odin)
  1	package apcli
  2
✓ 12ms exit 0
```

- `◆`：工具开始。括号里是压成一行的参数摘要，过长会截断。
- 缩进两格的内容：工具输出。成功但没有增量输出时，会补一段结果预览。
- `✓`：工具成功，后面是耗时和退出码。
- `✗`：工具失败，后面是错误。
- `… [scope]`：可重试错误。
- `! [scope]`：不可重试错误。
- `cancelled [scope]`：已取消。
- `turn ended: <reason>`：本轮不是正常 `stop` 结束。

工具输出超过 200 行或 20000 字节时会截断，并提示完整内容在 transcript。`bash` 的实时流不截断。

## 怎么判断这一轮结束得好不好

看 `stop_reason`：

| 值 | 含义 | 你该做什么 |
| --- | --- | --- |
| `stop` | 模型正常说完 | 读答案 |
| `max_tokens` | 单次回答达到上限 | 让它继续，或缩小任务 |
| `max_steps` | 达到单轮步数上限 | 增加 `--max-steps`，或拆任务 |
| `cancelled` | 被信号取消 | 检查已产生的副作用 |
| `context_too_long` | 上下文超限，且没有完成交接 | 开新会话，或启用自动交接 |
| `handoff` | 已生成交接文档并创建新会话 | 用新 session id 继续 |

`text` 格式的 stdout 只有最终文本。想区分“正常说完”和“被截断”，用 `--output-format json` 读 `stop_reason`。

## 怎么中断

命令行没有交互式取消键，取消来自信号：

- 按一次 Ctrl+C：设置取消标志，退出码 130。
- 1 秒内再按一次：直接退出，不再写收尾事件。
- SIGTERM：退出码 143。

取消会中止 HTTP 请求、终止工具和子代理的进程树。已经产生的副作用不会回滚。写了一半的文件、执行过的命令、残留的临时文件都按实际状态保留。

`ap-tui` 运行中按 Ctrl+C 会同时终止界面和 `ap` 子进程，不会回到输入框。

## 它到底改了什么

ap 不自动提交 git。要确认修改，用：

```sh
git diff
git status
```

需要完整过程时，去 transcript 里查：

```text
$AP_CONFIG/projects/<project_hash>/<session_id>.jsonl
```

transcript 只追加，不改写。工具参数、工具结果和最终文本都在里面。大块内容会写到同目录的 `blobs/`。

## 退出码

| 码 | 含义 |
| --- | --- |
| 0 | 正常结束，包括 `max_steps`、`max_tokens` 和 `handoff` |
| 1 | 内部错误，例如 transcript 写入失败 |
| 2 | 用法、配置或恢复错误 |
| 3 | 模型接口错误，或关闭交接后的上下文超限 |
| 4 | 工具基础设施故障 |
| 130 | Ctrl+C 或 SIGINT |
| 143 | SIGTERM |

退出码 0 不代表模型把话说完。结合 `stop_reason` 一起看。
