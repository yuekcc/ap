# 7. 会话管理

一次对话就是一个 session，由 `session_id` 标识。id 形如：

```text
ses_20261022_120000_abcdef123456
```

会话历史写在 JSONL 文件里，只追加，不改写。恢复时只读历史，不重新执行工具，也不调用模型补写摘要。

## 新会话

不传 `-s` 和 `-c` 时，每次运行都是新会话。

```sh
./build/ap --print "检查这个仓库的测试入口"
```

运行结束后，stderr 会打印 `continue with -s <session_id>`。

## 继续最近的会话

```sh
./build/ap -c --print "继续"
```

`-c` 在当前项目内找最近修改的根会话。判断依据是文件修改时间和最后一个 `session_start` 的父会话字段。子代理会话不参与。

“当前项目”由启动目录决定。从子目录启动会落到不同项目，找不到父目录的会话。

## 恢复指定会话

```sh
./build/ap -s ses_20261022_120000_abcdef123456 --print "把刚才的结论整理成三点"
```

`-s` 只在当前项目内查找。找不到时会退出 2，并打印期望的文件路径。最常见的原因是启动目录变了。

`-s` 和 `-c` 互斥。

## 从历史分叉

```sh
./build/ap -c --fork-session --print "换一个方案，从历史分叉"
```

分叉会复制源会话的全部完整事件到新文件，生成新的 session id。源会话保持不变。分叉是独立的根会话，`resumed_from` 指向源 id，但不再继承父子链。

blob 不复制，按内容哈希共享。删除 blob 会同时破坏源会话和分叉。

## 手动交接

上下文快满，或者你想主动把工作交给一个新会话时，用 `--handoff`。它必须和 `-s`、`-c` 或 `--fork-session` 一起用。

只创建交接会话，不立刻跑任务：

```sh
./build/ap -s ses_20261022_120000_abcdef123456 --handoff
```

它先生成交接文档，再创建新会话，然后打印新 session id。

交接并立刻继续：

```sh
./build/ap -s ses_20261022_120000_abcdef123456 --handoff "继续完成剩下的测试"
```

这段文本既是交接的聚焦提示，也是新会话的第一个 turn。新会话跑完后正常输出结果。

交接不是 fork。新会话会重新组装 system prompt，使用当前的模型、工具集、`AGENTS.md` 和技能。源会话必须至少有一条用户消息，否则退出 2。

浏览器界面在输入框下方提供同一个入口，见 [第 11 章](11-web.md) 的「手动交接」。

## 自动交接

默认开启。上下文真的不够用时，ap 会自动生成交接文档并创建新会话。你不需要手动加 `--handoff`。

两个开关：

- `--no-handoff`：只关闭自动交接。上下文超限时退出 3。
- `--context-window 0`：关闭整套上下文管理，包括预算和自动交接。手动 `--handoff` 仍然可用。

## 恢复后什么不会变

恢复以 transcript 里的冻结值为准。以下内容不会重新计算：

- system prompt。
- 模型。
- agent。
- 工作目录。
- 工具集。

因此恢复时不会重新读取 `SYSTEM.md`、agent 定义文件、记忆文件或技能目录。传了与冻结值不同的 `--model` 或 `--agent`，ap 会在 stderr 打 warning 并忽略。

`--max-steps` 和 `--max-tokens` 不在冻结范围，恢复时照常生效。

## 会话文件在哪

```text
$AP_CONFIG/projects/<project_hash>/<session_id>.jsonl
```

`$AP_CONFIG` 默认是 `~/.ap`。`project_hash` 由规范化后的启动目录算出。同一个目录在不同大小写、符号链接或尾斜杠下会落到同一个项目。详细布局见 [第 16 章](16-data.md)。

不要手改 transcript。恢复时唯一允许的物理改动是截掉崩溃留下的不完整尾行。
